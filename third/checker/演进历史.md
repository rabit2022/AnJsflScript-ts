### 1. 早期版本 (Netscape 时代)

在 ES6 之前，JavaScript 的版本号比较混乱，主要有 Netscape 的实现版本和 ECMA 的标准版本两条线。

📜 JavaScript 版本演进表 (Netscape -> Mozilla)

这段历史主要由 Netscape 公司（后来的 Mozilla 基金会）主导，它们的版本号（JS 1.x）与 ECMA 国际标准（ES x）并不总是一一对应。

| 版本代号         | 正式名称             | 年份   | 关键特性与历史地位                                                                                                             |
|--------------|------------------|------|-----------------------------------------------------------------------------------------------------------------------|
| **JS 1.0**   | JavaScript 1.0   | 1996 | **诞生**。Netscape Navigator 2.0 内置。最初的版本，有很多 bug。                                                                       |
| **JS 1.1**   | JavaScript 1.1   | 1996 | **标准化开端**。对应 **ECMAScript 1 (ES1)** 的草案，增加了数组对象等。                                                                     |
| **JS 1.2**   | JavaScript 1.2   | 1997 | **不兼容风波**。Netscape 4.0 内置。它试图加入动态 HTML 特性，导致**不兼容**当时的 ES1 标准。                                                        |
| **JS 1.3**   | JavaScript 1.3   | 1998 | **回归统一**。Netscape 4.5 内置。完全兼容 **ECMAScript 2 (ES2)** 和 ES3 草案，加入了 `Date` 对象等。                                         |
| **JS 1.4**   | JavaScript 1.4   | 1999 | **服务器端**。主要在服务器端（Server-Side JavaScript）使用，浏览器中几乎没有广泛部署。                                                              |
| **JS 1.5**   | JavaScript 1.5   | 2000 | **经典大版本**。Netscape 6/7 内置。完全对应 **ECMAScript 3 (ES3)** 标准。加入了 `try/catch` 异常处理。这是 Web 开发历史上统治了近 10 年的基石版本（兼容 IE6-IE8）。 |
| **JS 1.6**   | JavaScript 1.6   | 2005 | **Firefox 时代**。Firefox 1.5 内置。加入了 **E4X** 、数组推导、`let` 关键字等。**注意：这些特性未被其他浏览器广泛支持**。                                    |
| **JS 1.7**   | JavaScript 1.7   | 2006 | **实验性**。Firefox 2 内置。加入了生成器（Generators）、迭代器（Iterators）等。                                                              |
| **JS 1.8**   | JavaScript 1.8   | 2008 | **ES5 前夜**。Firefox 3 内置。加入了 `strict mode` (严格模式) 的早期实现、`JSON` 支持等。                                                    |
| **JS 1.8.5** | JavaScript 1.8.5 | 2010 | **接轨 ES5**。Firefox 4 内置。正式完全支持 **ECMAScript 5 (ES5)**。                                                                |

### 💡 为什么“1.5 没有”或者“1.6 很突兀”？

1. **关于 JS 1.5 的“隐形”**：
    - 虽然它叫 JS 1.5，但在行业标准中，它被称为 **ECMAScript 3 (ES3)**。
    - 因为 ES3 标准太过于普及和经典（几乎所有的老式浏览器都支持），开发者更习惯称它为 ES3，导致“JS 1.5”这个名字在历史长河中被
      ES3 的光芒掩盖了。
2. **关于 JS 1.6 及之后的“突兀”**：
    - **JS 1.6、1.7、1.8 是 Mozilla 的“独角戏”**：在那个年代（2005-2008），浏览器大战再次激烈，其他浏览器（IE, Chrome,
      Safari）并不买账 Mozilla 这些超前的特性（如 E4X）。
    - **为了兼容性，大家不敢用**：因为只有 Firefox 支持这些新语法，为了保证网页能在所有浏览器运行，绝大多数 Web 开发者被迫停留在
      ES3 (JS 1.5) 的语法水平上，不敢使用 JS 1.6+ 的新特性。
    - **直到 ES5 (JS 1.8.5) 才再次统一**：直到 2009 年 ES5 标准发布，各大浏览器再次达成一致，JavaScript 才迎来了下一次全行业的大统一。

**总结来说：**

- **JS 1.5 = ES3**（非常经典，你肯定用过，只是不知道它叫 1.5）。
- **JS 1.6** 是 Mozilla 在 ES3 和 ES5 之间“空窗期”里，为了探索新特性而发布的**浏览器专属版本**，由于缺乏跨浏览器支持，它更多是一个“历史注脚”。

### 2. 📉 标准化确立期 (ES3 -> ES5)

这个时期确实是 JavaScript 发展史上至关重要的“蛰伏”与“奠基”阶段。从 1999 年到 2009 年，虽然标准版本号只从 ES3 更新到了
ES5，中间经历了长达十年的迭代缓慢期，但这期间语言本身从“浏览器玩具”逐渐蜕变为成熟的工程化语言。

| 版本代号    | 正式名称         | 发布年份      | 关键特性与历史地位                                                                                                                                                                                      |
|---------|--------------|-----------|------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **ES3** | ECMAScript 3 | 1999      | **真正的奠基者**。这是 JavaScript 历史上第一个**成熟且被广泛支持**的版本。它引入了 `try-catch` 异常处理、正则表达式、`switch` 语句以及对数组和字符串的大量增强（如 `push`、`concat`）。在随后的 10 年里，它成为了前端开发的“最低兼容标准”。                                          |
| **ES4** | ECMAScript 4 | 2008 (草案) | **夭折的激进派**。这是一个极其激进的版本，计划引入模块、类、类型系统等。但由于 Adobe (Flash) 和 Microsoft 等巨头之间的分歧过大，该草案在 2008 年被委员会**废弃**。它的很多思想后来被“稀释”并融入到了 ES6 中。                                                                 |
| **ES5** | ECMAScript 5 | 2009      | **现代化的分水岭**。为了修补 ES3 的缺陷并吸取 ES4 的教训，ES5 采取了稳妥的升级策略。它引入了**严格模式 (**`"use strict"`**)、原生 JSON 支持、数组的高阶函数 (**`map`**, **`filter`**, **`reduce`**)** 以及 `Object.defineProperty`（这是 Vue 2 响应式原理的基础）。 |

### 💡 为什么这 10 年如此“漫长”？

你可能会好奇，为什么从 ES3 到 ES5 隔了整整 10 年？

- **浏览器垄断**：在 2000 年代初期，Internet Explorer 6 (IE6) 占据了绝对主导地位。由于缺乏竞争，微软对跟进新的 Web 标准缺乏动力。
- **标准冻结**：由于 ES4 提案的失败和社区分裂，ECMA 委员会在这段时间内主要专注于维护和微调，导致标准发展几乎停滞。
- **开发者的痛苦**：虽然标准停滞，但网页应用的需求（如 Gmail、Google Maps）却在飞速增长。这导致开发者不得不使用各种“黑科技”和大量的兼容性代码来应对不同浏览器的差异，直到
  ES5 和现代浏览器的出现才逐渐好转。

### 3. 现代化爆发期 (ES6/ES2015 -> 现在)

从 2015 年开始，JavaScript 进入了“一年一发”的快速迭代时代。

| 数组并集   | `_.union(a,b)`                    | `[...new Set([...a,...b])]`      | ES6    |

Intl 对象是 JavaScript 中用于处理国际化（i18n）的核心 API。它并非在某个单一时间点一次性推出，而是随着 ECMAScript 标准的演进，经历了从
**基础功能**到**全面完善**的渐进式发展过程。

### 📅 Intl 对象历史演进表

| 时间节点                   | 版本/标准                      | 关键特性与组件                                                            | 说明                                                                                                                                |
|------------------------|----------------------------|--------------------------------------------------------------------|-----------------------------------------------------------------------------------------------------------------------------------|
| **2015年**(ES2015/ES6)  | **Intl 基础设施**              | `Intl`** 命名空间**`Intl.CollatorIntl.NumberFormatIntl.DateTimeFormat` | **奠基之年**。随着 ES6 的发布，Intl 作为内置对象首次标准化。这四大组件构成了国际化的基石，分别用于字符串比较、数字格式化和日期时间格式化。                                                      |
| **2018年**(ES2018)      | **ECMAScript 国际化 API 1.0** | `Intl.PluralRules`                                                 | **填补空白**。该版本正式标准化了复数规则处理。在此之前，判断“1 条消息”还是“2 条消息”通常需要依赖复杂的 if-else 或第三方库，`PluralRules` 提供了原生的、多语言支持的解决方案。                          |
| **2019年**(ES2019)      | **ECMAScript 国际化 API 2.0** | `Intl.ListFormatIntl.DisplayNames`                                 | **列表与名称显示**。`ListFormat` 可以将数组格式化为符合当地习惯的自然语言列表（如英文的 "A, B, and C"）。`DisplayNames` 则用于获取语言、地区、货币等的标准名称（如将 'zh-CN' 显示为 '中文 (中国)'）。 |
| **2019/2020年**(ES2020) | **ECMAScript 国际化 API 3.0** | `Intl.RelativeTimeFormat`                                          | **相对时间**。用于格式化相对时间（如 "2 天前"、"in 3 hours"）。虽然提案在 2018 年左右就已出现，但其广泛普及和标准化完成主要集中在这一时期。                                               |
| **2024年**(ES2024)      | **ECMAScript 国际化 API 5.0** | `Intl.DurationFormat`                                              | **时长格式化**。这是较新的特性，专门用于格式化时间间隔（时长），例如将秒数格式化为 "2小时30分钟"。                                                                            |

### 💡 补充说明

- **Polyfill 的作用**：虽然上述 API 是在特定年份标准化的，但在实际开发中，为了兼容旧版浏览器（如 IE11 或更早的
  Chrome/Firefox 版本），开发者通常会使用 **Polyfill** 库（如 `@formatjs/intl` 或早期的 `Intl.js`）来提前使用这些功能。
- **持续更新**：Intl API 仍在活跃开发中，除了上述主要对象外，还不断在细节上进行优化，例如对 `Intl.DateTimeFormat`
  时区支持的增强，以及对不同语言排序规则（Collation）的完善。

这份表格展示了 JavaScript 国际化能力从最初的“能用”（格式化数字和日期）到现在的“好用”（处理复数、相对时间、列表）的完整进化路径。
